## Honest-limits block (must accompany capability claims)

- The gate is certain only about what it **blocks**. An unmatched action is *unchecked*, not *safe*.
- Lookup/fact-check channel is **empty by default** (bring your own fact base). Not a hallucination detector.
- Prompt-injection defense is experimental and off-headline.
- Framework adapters are in-process convention; **only the Claude Code hook is enforcement outside the agent's control flow**.
- Signal is strongest on 7–30B local models; weaker on frontier (F6/F7).

## Process

1. New number → new row (with source + pin) BEFORE it appears in any copy.
2. Version-scoped numbers (tests, bypass count) get re-pinned at each release; old numbers stay valid only in version-scoped contexts (e.g. CHANGELOG).
3. TODO rows must be resolved (artifact pinned) before the number is used in NEW copy.
4. **Every corpus-derived number carries its measurement date AND the dataset version it was taken at** — for HuggingFace sources that means the repo id *and the split name*, because upstream renames splits without notice. A corpus figure quoted bare ("1M commands") is not a claim, it is a rumour. This rule exists because it was missing: the 1,085,159 figure went unchallenged for three weeks while it double-counted a dataset, and the 2026-07-28 re-run silently lost two SWE-Gym sets to a `train` → `train.raw` / `train.success.oss` rename that only a live split read caught (see F1b).
5. **Re-measure, never re-derive.** A number is refreshed by running its artifact script again, not by scaling the old number or find-replacing it across files. When a headline number changes, the old artifact stays on disk as the historical record and the new row says explicitly what it supersedes and why.
